# 偶发提前 ARR 的计时修复（2026-10-20）

本次没有人工复现用户实际游玩时的偶发现场，但构造出了与线程抢占、事件处理停顿有关的错误时序，新增回归在修复前失败。

## 原因与修复

`process_buffered_player_input_frame` 接收的本轮时间先于输入读取。如果线程记录了 20 ms 后被暂停，恢复时读到 120 ms 的按键，原来的 `min(now, eventTime)` 会把按下时间改成 20 ms。DAS 设为 90 ms 时，130 ms 的下一轮就会开始重复，此时实际只按住了 10 ms。

现在保留输入事件的原始时间。本轮时间尚未到达的事件留在队列里，下一次推进再处理；不丢弃按下、松开或后续命令。进块、倒计时和暂停预充能也保留原始按下时间。关闭预充能时的计时重置使用较晚的时间，避免旧采样再次把新按键向前挪。

另一个回归覆盖采样停顿期间进块：已知只按住 80 ms，新的方块在 200 ms 出生时，原来的出生时间下界会把重复计时直接抬到 200 ms，绕过 90 ms 的 DAS。现在动作作用时间仍不早于方块出生，但横移和软降的重复计时单独受采样时间及当前事件原始时间限制；出生时间不能增加按住时长，迟到的松键也不能先在出生时触发重复。

图形主线程原来在处理完一批 SDL 事件后读取采样完成时间。若事件处理过程中停顿，此时新松键可能还在等待下一次 pump，引擎却已把这段停顿当作持续按住。新增 `InputSample` 在 pump 前记录边界，只允许本批实际收到的非自动重复键盘事件扩展边界；窗口、文本、鼠标处理和渲染耗时不能扩展它。pump 期间收到的新按键仍可在本批生效。

图形版的 SDL 输入转交与渲染共用主线程，Linux 终端版的 evdev 输入独立采集。这使上述时序问题更容易在图形版负载变化时暴露，是对用户现象的合理解释，尚不能证明它是实机偶发的唯一来源。

## 影响与验证

- 最终使用 `CTEST_PARALLEL_LEVEL=4 ./compile.sh --test --frontend both` 重建两端，Linux 完整 CTest **169/169 通过**，含图形完整应用、输入、回放、联机、Bot 和架构边界。
- DAS、ARR 数值及阈值算法没有调整；两端继续共用一套玩法输入处理。
- 回归覆盖旧本轮时间读取到新按键、进块和暂停预充能、关闭预充能、慢 pump、慢事件处理、左右方向、ARR 为零、自动重复、短按松开及 30–1000 Hz 的输入推进。
- Linux 使用注入事件的真实时钟探针中，DAS 为 50/100/200 ms 时，两端首次重复均未提前，包含与 Bot 压力测试并行的一次检查；另有 1080 组采样时序比较。这些检查不测量物理键盘或显示器反馈延迟。
- Linux OpenGL 离屏隐藏冒烟在 30、240 FPS 通过，使用独立临时数据，没有显示测试窗口或保存截图。
- 与 Bot 压力测试并行的一次固定 2.5 秒冒烟未完成预设的 Drop/Hold 操作；负载结束后，两种帧率均重新通过。该固定时间脚本不能替代高负载下的人工设备输入验收。
- Windows MinGW 编译器在隔离 Wine 环境中对本次共享代码、图形输入、主程序及回归测试的语法检查通过；没有完成原生 Windows 设备或显卡验收，原生验收记录保持待验。
- 保留全部键盘入口、配置、回放和网络格式；本次不涉及发布。
- 本地 `.tetr` 的 214 个文件在验证前后大小和 SHA256 一致，测试没有写入个人数据。

修复集中在共享的 `player_input.h/.cpp`、`manual_input.cpp`、`input_precharge.cpp`、`movement_input_state.cpp`、OpenGL 的 `input.h/.cpp` 与 `main.cpp` 及对应输入回归。回退应仅撤销本次计时和回归增量，保留这些文件中已有的其他本地修改，不替换或清理 `.tetr`。
