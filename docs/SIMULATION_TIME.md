# 按完成落块推进时间（2026-09-24）

## 配置与行为

- `Settings / GAME / Simulation PPS`，磁盘同名，默认 0。
- 0 使用原来的游戏时钟；正数 x 每完成一块推进 1/x 秒。
- 完成指方块锁定、攻击/抵消和消行动画结束。HOLD 不计数；出生碰撞死亡不计数。
- DAS、ARR、软降、自然下落、锁定延迟、BOT PPS 和动作展示、消行动画使用真实时间。
- 游戏经过时间、Blitz、定时垃圾、缓冲区年龄、QP 高度/速度/难度变化、spike 和统计使用模拟时间。
- `GAME / Turn Pieces` 是每轮块数 y，默认 0（关闭），正数可设 1e-9 至 1e6。双方 y>0 时交替，Player 1 先行；x=0 也可交替。双方 x>0 时设置 y=x 可恢复按模拟秒交替。
- 每方在第 n 轮累积完成至少 n*y 块；y=2.5 时各轮 3、2、3、2……块。对 y<1，已完成块覆盖的后续空轮次会直接跳过。
- 任一方 y=0 时取消交替。双方计时始终各自由 x 决定：x>0 按落块计时，x=0 按真实时间计时。

## 实现

`GameContext::now()` 为游戏规则的时钟，`real_now()` 用于操作、表现和轮询。
会话保存完成块数与模拟时刻；每块目标时间直接由块数/x 求出，避免逐块累加误差。
`Engine::advance_piece_time()` 在消行动画结束后执行，以至多 50 ms 的内部步骤
结算时间跳跃中的事件，并精确命中定时垃圾与 QP 每秒更新的边界。这些内部步骤
不允许玩家操作或新块生成。若期间收到对局结束信号，仍完成整块的时间推进再返回。

`Engine::wait_for_piece_turn()` 位于出块循环入口，HOLD 延续不重新交棒。
本地和联机共用同一套进度协议，以完整完成的放置块数确认进度，支持 x=0。
等待时冻结出块与操作，双方的游戏时钟均暂停，包括 x=0 的一方。操作与动画仍使用真实物理时间。同时轮询攻击、
对局结束、Retry 和 Settings。重新轮到该方时，BOT 节奏从真实时间重新计时。

完成 k 块后，该方可直接确认到 `floor(k/y)` 轮，包含由跨界余量覆盖的空轮次。
Player 1 需要对手确认至少同一轮，Player 2 需要对手确认更高一轮后才继续出块。
双边 y=1e-6 时，进度直接从 0 跳到 1000000，不发送或处理百万个空轮次；计算量
与实际完成块数相关。整数边界容忍 double 十进制表示的舍入误差。

联机 setup 在 x>0 或 y>0 时附加 `piece-time-v2`、x、服务器分配的玩家序号和 y。
解码仍接受 v1，并将其每秒窗口解释为 y=x。启用新设置需更新服务器和客户端。
双方倒计时完成后服务器发送 RoundReady，避免先准备好的一方提前出块。
`!piece-turn` 帧携带本局 seed 与已完成窗口计数，100 ms 重发；接收方忽略旧局
帧、重复帧及倒序进度。旧攻击帧与棋盘编码不变。启用本功能的联机需要同步更新服务器。

Replay 配置使用可选 SimulationPPS 字段，并始终保存 TurnPieces（包括 0）。
完全不含新字段的旧文件读取为 x=0、y=0；含正数 SimulationPPS 但省略 TurnPieces
的旧文件沿用当时省略字段所代表的 y=1。
新参数使用严格浮点解析，支持十进制和科学计数法，拒绝 NaN/Infinity，避免微小配额丢失。
新交替对战为每条事件额外记录 `wall_time`，两侧使用同一真实时间原点。读取后
Operation.timestamp 用于播放调度，gameTimestamp 用于各自的游戏计时、缓冲区和统计。
x=0 的等待区间记录 pause_game_time / resume_game_time，回放和断点均保留暂停状态。
回放在生成下一块及更新 NEXT 之前等待该方的 StartPlace，且由共享完成块数限制交棒；
HOLD 延续保持当前回合。暂停、倍速、跳转使用共同的播放时间，断点同时保存游戏时刻和块数。
消行动画从记录的 ClearLine 时刻开始计算，避免高速追赶时把动画结束推到录像末尾之后。
旧交替文件没有真实时刻，按配额直接重建双方先后顺序，略过空轮次。真人思考及等待时长
无法从旧文件恢复，动画与移动节奏只能近似；x=0 的旧文件仍按当时的同时运行方式播放。

## 设置与显示

Settings 先展示单列类别，Local Versus 的双方各占一页，以 `PLAYER 1 / SETTINGS`、
`PLAYER 2 / SETTINGS` 为标题，左右切换；高亮表示当前选中的类别。
类别沿用白色文字、金色选中高亮，SETTINGS 和玩家标题使用原有橙色；隐藏颜色模式仍遵循原设计。
详情左右切页，P 返回类别列表，R 在所有层级重开；选择列表、数值/文本输入、
键位捕获均可中断，终端输入模式通过作用域恢复。菜单按键重复使用真实时钟。
首层记住最后选择的玩家/类别，第二层按玩家和类别分别记住子条目。返回上层、
左右切页、任意层 R 重开后再进入均恢复选择；仅浏览首层后重开也会记忆。
这些位置保留于当前程序会话，不写入配置文件。
从 Local Versus 切换到其他模式时，继续显示 MODEL 详情层，后续修改归属被选中的玩家；
切回时直接显示 Player 1 的 MODEL 详情页，并恢复双方各自的参数。RESET 分别作用于当前
玩家全部设置或当前类别；参数自动保存到 `.tetr/`，菜单光标位置仍只保留在当前会话。

PPS 左侧的 `100000` 残留来自零时刻除以极小数及变短数字未完全擦除。
零时刻现在显示 0 PPS / APM，统计栏记住上次宽度并擦除整个旧数字。

## 验证

`simulation_time_test` 覆盖配置和 Replay 兼容、真实等待不推进模拟时间、重开重置、
跨多个周期的定时垃圾、垃圾缓冲成熟、QP 更新、Survival 生成、消行动画完成边界、
真人自然下落与锁定、BOT 真实 PPS、HOLD、实际出块循环交替、等待方不出块、
单方 0 的回退、协议无效输入和旧局/重复通知、完整时间步结算。
配额场景包括双方不同的 2.5/1.5、0.5/1、1/1、1e-6/1e-6、1e-6/2e-6、
1e-9/1e-9，并验证 0.1 的整数边界、默认 0、单方 y=0 和 x=0 时的交替。

`turn_replay_test` 验证真实记录时刻与游戏时间分离、暂停、旧录像重建、断点块数恢复，
以及实际出块循环在全部事件已到期时仍严格按小数/极小配额交替。
`line_clear_presentation_test` 覆盖末尾消行动画的追赶；初始化测试覆盖回退重建时每局统计清零。

`settings_menu_test` 通过注入按键驱动实际菜单，检查类别/详情切换、左右换页、
P 返回、各层级 R 重开、双人类别和独立绑定、切换为双人时的设置继承，以及模拟
时间冻结时按住方向键仍会重复移动。`render_layer_test` 覆盖零时刻 PPS 和数字缩短擦除。
