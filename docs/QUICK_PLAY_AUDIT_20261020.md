## 仍未实现或只完成部分的机制

| 机制 | 当前状态与缺少的部分 |
| --- | --- |
| 快速游戏公共大房间 | 目前是本地统计压力模拟。没有随进随打的真实 QP 房间、服务端攻击目标分配、榜首目标权重、对手海拔与身份、对手预览和房间排行榜。3/5/7 分钟增加受击权重及受击保护影响选人的公式，也没有作为真实房间权重运行；本地仅校准平均压力并近似危险/垃圾减免。普通多人对战不等于这一套房间机制。 |
| 攻击切片与犹豫合并 | 本地模拟没有“发送拆成最多 4 行的单元 → 服务端逐片重新选目标 → 接收端按发送者和同帧合并”的 QP 流程。现有 Windup 是收到大攻击后的分段，不能替代发送切片。 |
| 击杀奖励 | 没有 QP 攻击归属和击杀事件，因而没有普通击杀 `15 × 等级 × .25 m`、rEX/被击杀者 SB 时 `8 × 等级 × .25 m` 的奖励。 |
| Duo / 2P | 没有双人共享爬升、发送减半、双倍抵消、队友死亡受击加量、贡献差保护及复活任务。文档中的 F～X 任务池、按楼层和累计复活次数选择任务、PN 的专属复活任务也未实现。本地双人对战是另一玩法。 |
| 逆位 Duo / r2P | 整套未实现：攻击反伤优先给队友、队友死亡锁高度、等级上限 4、特殊疲劳时间线及最终禁用复活。现有 BF/rBF 不能代替它。 |
| Hyperspeed | 没有按前五层等级阈值进入、低等级退出、十层完成的状态，也没有分层计时、个人最佳分段对比和对应成就。基础升级和跳级已经存在。 |
| rVL 洞位预告 | 三倍受击、14 高场地、固定高易挖度和集中已存在；缺少官方提前生成并展示两个洞位的队列，两端都没有该预告。 |
| rNH 双宽洞的方向状态 | 已有无暂存、纯随机、一个预览、无投影、Mini 和双宽洞。第二个洞尚未复刻官方持久的左右方向、按楼层概率翻向及边界处理；目前使用通用连续双洞形状。 |
| Mod 组合的额外目标 | 未实现组合专属的命名、成就和计数，例如 EX+MS 的前 400 块总攻击、MS+DH+AS 的 Spin 挖掘目标。一般 Mod 效果叠加已存在。 |
| 官方展示与档案 | 没有完整的楼层名称演出、疲劳叙事、原作音乐/音效、推进器动画和官方在线记录系统。两端已有简化的高度、等级符号、预警和回放。 |
| 完整的原作确定性与逐帧时钟 | 本地 QP 的出块/垃圾随机源、攻击者模拟、实际帧时间积分和原作固定 60 Hz 状态机并不完全相同，不能保证同 seed 得到整局相同的 QP 结果。现有其他模式的 TETR.IO 回放互通不表示 QP 房间可逐帧复现。 |

以上是缺项清单，本轮没有把 Duo、公共房间或 Hyperspeed 标记成已完成。

## 本轮修正

修改全部位于共享 Rules/Engine/配置与回放层，两端使用相同规则，BOT 的通用 QP 预测也同步采用共享实现。

| 问题 | 修正后的行为 |
| --- | --- |
| 集中洞位判定错误 | 原来用受击保护削减后的连续改变率 `Y` 判断；现改为官方在保护削减前的原始 `X <= .15`，且限前五层，rVL 仍强制开启。普通模式前五层开启；EX 第三层的浮点边界与官方一致。 |
| 集中范围固定排除两列 | 依场宽排除左右各 `round(W/5)` 列，兼容 SB 成长和自定义宽度。 |
| 易挖度排序依据错误 | 采用当前官方引擎的列顶高度，加“最底部未填满行含灰格时，其第一个洞”的横向距离；空列分数为 0。主机和 BOT 共用计算，首包也应用洞位偏好。 |
| 不同列抵消减免过早 | 前两种列只建立历史；第三种新列才获得额外减免。重复列更新最近使用顺序，Spin 消四也有消四减免，5 行按官方 QP 的消四分支处理，更多行不误套消四减免。I 消四使用实际占用列，避免同一列的两种竖向旋转被当成不同列。 |
| 抵消状态结算顺序错误 | 75 块检查在先，挖掘清零及 Spin/消四减免随后，全消 +3 和本次抵消量最后加入，避免本次 PC/抵消被错误清零。75 块只触发一次，直到减免或新受击重置计数。 |
| VL/rVL 的等待时间被错误减半 | 连续抵消达到 25 时，VL/rVL 不触发该减半。保留项目已约定的 rEX 楼层等待时间优先策略。 |
| rEX 停层和疲劳相乘 | 两者是同一接收倍率的加量，改为相加。例如各 +50% 时总倍率为 2，而非 2.25。 |
| rDH/rAS 重力错误增长 | 关闭这两种逆位的自然重力增长；真人、按块时间和 BOT 预测一致。 |
| rDH 每次受击上限错误 | 从 8 行改为 2 行，挖掘补行仍由独立的直接加行入口处理。 |
| rDH 错误累积 B2B | 按公开引擎禁止其 B2B 累积；普通消四和 Spin 不再在该 Mod 下建立 B2B。 |
| BLIGHTED 倍率总向下取整 | `1.75 × 攻击` 改为小数概率取整；消除非垃圾行而消耗效果时再 +1。主机使用独立取整抽样，BOT 按保守下界评估。 |
| 推进器更新顺序错误 | 先流失经验再检查升级；刚好满经验且没有保护时可能不升级。新升级获得完整保护，升级疲劳恢复使用本次升级前等级的半条阈值；跳级不提前放大本帧自然爬升。 |
| 自然爬升和奖励混在一起 | 自然爬升直接增加高度，其卡层减速只看当前高度；待释放攻击奖励另行释放。rEX 先下坠再释放奖励，小于等于 .05 m 的奖励尾量一次释放。 |
| 越层漏算/误算 | 按消行、抵消、发送的动作顺序检查，并把本次发送的高度计入距离；只有剩余距离在 `[0,2] m` 才 +3 m，已经超出的情况不再错误奖励。 |
| rAS 800 m 限制范围错误 | 高度至少 800 m、累计挖掘不足 5 行时，按当前公开 `AwardLines` 路径禁止所有该路径经验，保留高度奖励。 |
| 疲劳永久垃圾按一秒一行 | 改成官方常量中的逐帧时刻，正常三波 2/3/5 行，rEX 三波 3/5/12 行。波内先间隔 30 帧，再逐渐延长，不能统一按每秒一行处理。 |
| 危险状态少算一行 | 危险区改为可见场地顶部五行，匹配原始引擎的高度阈值；真实服务器的目标分配仍未实现。 |
| 20G 暂存换块接受不可达落点 | 原生 QP 搜索和 BOT 公共适配器验证暂存换块时，先让换入块按即时重力落地，再验证路径，避免接受只能从空中横移到达的目标。该公共校验对其他 BOT 同样生效；Cold Clear 的初始搜索状态存在相同问题，也改为先落地再枚举动作。 |

## 文档与当前代码不一致的地方

1. 社区“垃圾集中”文字写连续改变概率，但当前原始 `zthm.Update()` 检查的是保护扣减前的 `messiness_inner`。采用当前代码，并保留 EX 第三层浮点边界。
2. 社区易挖度描述使用最低空格和最浅垃圾洞；当前 `atm.RerollColumn()` 使用列顶高度和最底未满行的首洞。采用当前代码，并以多种版面与正负 favor 对拍验证。
3. 社区描述抵消经验有 50% 基础折扣及连续抵消惩罚，当前公开 `AwardLines` 本身没有这个折扣；专家抵消的公开路径还可能获得 `.05` 经验。服务端/历史版本关系不能仅凭客户端断定。保留项目原有的社区折扣与专家零抵消经验约定，未把这一差异混入“完全一致”的测试结论。
4. 社区对 rAS 的 800 m 限制只写发送经验；当前公开函数的限制覆盖该函数的全部经验。本轮按公开函数修正。
5. rEX 最终网络发送包减半不等于攻击统计或发送经验减半。TerMino 没有真实 QP 外部接收者，本轮未通过减半本地统计来冒充该网络行为。

## 保留的项目约定

- 全消攻击、全消 B2B、Surge 等服从项目已有的可配置攻击规则；当前默认全消 5、全消 B2B 总增量 1，不强行恢复原作固定的 3 和额外 2 次。
- 连续抵消默认关闭，可用 `--qp-continuous-cancel` 启用；rEX 等待时间表始终优先。
- rSB 的 DAS/ARR 依既有约定强制为 0 秒，官方观察文档的 .3 帧值保留为差异记录。
- Mod 免费选择，并允许逆位组合；没有引入官方解锁高度、会员/季节门槛及逆位互斥限制。BF、SE、Extended AS 等已有扩展保留。
- 继续使用项目实际帧时间，包括长帧的连续降级积分；本轮没有为追逐原作边缘异常而引入负等级或 NaN。

## 回放与验证

新录像写入 `QPRulesVersion=2`。缺失该字段或显式版本 1 的旧录像使用核查前规则，包括旧洞位、经验、抵消和疲劳时序；不迁移或重写本地 `.tetr`。原有录像操作格式继续解析。

`tests/quick_play_reference_test.cjs` 通过已有 SHA-256 锁定的加载器，执行官方原始引擎的 `zthm.Update`、`AwardLines`、`atm.RerollColumn` 和原始疲劳常量。仅提供运行上下文与输入，不复制或重写官方函数；官方 JS 仅置于临时目录，不随项目分发。

```sh
node tests/quick_play_reference_test.cjs /path/to/reviewed/tetrio.js ./build/tests/tetr_rules_tests
```

对拍覆盖 216 组推进器、672 组奖励、160 组集中判定、30,204 个疲劳帧及 3,000 次洞位分布抽样，共 34,252 项比较。它不覆盖服务器分配，也不宣称整局 QP 已完全一致。普通 C++ 回归另检查连续抵消历史、受击重置、rDH 上限/取整/B2B、rAS 经验限制、按块时间重力和新旧配置版本。

测试同时更新了原有假设：垃圾形状检查按 rDH 的两行上限分批接收；危险区检查覆盖新五行/旧四行；SE 轨迹检查实际产生攻击的消一次数，避免把只能消一攻击的 Mod 按普通模式的固定总伤害门槛误判。其他模式的攻击门槛保留。

20G 暂存直接回归构造了右侧高台，确认目标从空中可达、落地后不可达，新校验必须拒绝；另通过 1,226 次使用真实落块与帧规则的连续轨迹检查。

平台覆盖为 Linux：`./compile.sh --frontend both` 构建终端、OpenGL、FT7 与服务端；OpenGL 用 `SDL_VIDEODRIVER=offscreen`、隐藏窗口和隔离临时数据通过键盘冒烟检查，渲染器为 Mesa llvmpipe。未运行原生 Windows 图形/输入验收，相关记录仍为 pending。

最终完整 CTest 为 **169/169 通过**（155.46 秒），官方原始引擎对拍 **34,252/34,252 通过**。本轮独立补丁、修改前快照、来源摘要和构建/测试日志保存在 Git 忽略的 `build-migration-backups/quickplay-audit-20261020/`；未改写本地 `.tetr`，未发布 GitHub。
