# Fusion 公开源码与 bot_chatgpt 的方向比较

2026-09-25。用户要求：参考 <https://github.com/MochBot/fusion> 与本BOT主体方向的差异，不照搬代码、权重或整套策略。本文是参考笔记与待验证假设，不是新候选、规则认证或测试成绩。

## 1. 来源与结论边界

Fusion 的 [README](https://github.com/MochBot/fusion) 将项目定位为 TETR.IO 回放指导引擎，包含搜索、估价和规则实现。不能据仓库归属认定它就是本项目所分析 mochbot 对战回放使用的完整程序；回放成绩与源码机制不建立未经证实的因果联系。

本轮通过 GitHub/raw 页面阅读 `eval.rs`、`analysis.rs`、`search_config.rs`，以及 `search_expand.rs`、`state.rs`、`versus.rs` 的相关实现和训练说明；另核对 `coach_beam.rs` 的入口说明。以下明确区分通用搜索、对战转移与指导专用搜索，不把单个文件代表整个引擎。

## 2. 估价的实质差异

| 方面 | Fusion 中确认的机制 | 当前 bot_chatgpt 与取舍 |
|---|---|---|
| 棋盘结构 | `eval.rs` 独立评价洞、覆盖负担、高度、平整度、井和几何搭建特征。 | 已有 Botris 的洞行、洞深、井深、行列变化及覆盖负担，不是缺少地形估价。独立的几何 TSD 搭建提示是一个差异，但不能等同于可达 Spin 路径。 |
| 评分组合 | 启发式路径分开组合棋盘、累计攻击、连锁和情境；连锁/情境有界，累计攻击和连锁按深度归一化。这里连锁塑形传入的是 **combo**。 | 当前累计折扣攻击/挖掘收益，加末端线性 B2B 存量和路径高度风险。值得检查尺度与重复计分，不支持直接提高 B2B 权重；也不能把 combo 公式改名移植为 B2B。 |
| 可选学习估值 | 有策略引导与逐子节点价值推理；逐子节点价值模式成功时不再简单叠加完整启发式总分，推理缺失/失败有回退。 | 当前没有神经网络。只读 `eval.rs` 不能解释 Fusion 的全部运行行为，更不能复现其学习模型或断言其胜率。 |
| 压力与状态 | 搜索的 `advance_lock` 与对战的 `advance_versus` 分离；前者对待入垃圾作简化，后者接收实际抵消后的队列状态。 | 我们已有可见包到时、FIFO抵消、消行暂缓、非消行上升预测，但未知洞位仍用高度偏移。不能将外部搜索模型直接当作更准确的宿主模拟。 |

依据：[棋盘估价](https://github.com/MochBot/fusion/blob/main/src/eval.rs)、[分项塑形](https://github.com/MochBot/fusion/blob/main/src/analysis.rs)、[搜索配置](https://github.com/MochBot/fusion/blob/main/src/search_config.rs)、[子节点评分与推理分支](https://github.com/MochBot/fusion/blob/main/src/search_expand.rs)、[状态转移](https://github.com/MochBot/fusion/blob/main/src/state.rs)、[对战垃圾队列](https://github.com/MochBot/fusion/blob/main/src/versus.rs)。

本地对应入口是 [evaluation.h](../src/bot/chatgpt/evaluation.h)、[policy.h](../src/bot/chatgpt/policy.h)、[forecast.h](../src/bot/chatgpt/forecast.h)，以及 `zzztoj_standalone/upstream/src/ai_zzz.cpp` 的 `Botris::eval`。默认攻击权重560、B2B权重480，combo延续额外项为0；高压挖掘混合策略保留为未启用实验。源码中的已有选项不能都算成生产策略。

## 3. 可以借鉴什么，不借鉴什么

- **借鉴分项审计，不照搬分值。** 将已产生攻击、待兑现链价值、地形与中途风险分别解释。检查同一收益是否在路径攻击与末端存量中重复计算，以及尺度是否使保链压过及时降高。这是待验证问题，尚未证明当前存在具体重复计分错误。
- **借鉴有限的机会价值，不奖励图案本身。** 如果后续证据支持估值候选，只给可见队列/HOLD下有合法出口、且能在压力到来前完成的结构估计机会价值；检查兑现后不再重复奖励。几何特征可以提供低成本提示，不能充当路径证明。P2失败后不借此重启第三轮同方向搜索配额试验。
- **借鉴参考实现对照测试。** Fusion 地形特征带有简明参考算法与优化算法的差分测试；我们应针对宿主与预测的边界写自己的用例，而不是迁入另一套规则。其 coaching 状态中的高度阈值和出生包络判断不能替代本项目的实际块型出生、Clutch及死亡规则。
- **不照搬搜索规模或未来队列。** Fusion 默认配置包含较大宽度/深度、静态延伸及7-bag队列扩展；这些配置不构成本机100ms、8 PPS的性能证据。已知队列之外的推测不得当成已知未来。
- **不把学习管线当作现成最强参数。** [训练说明](https://github.com/MochBot/fusion/blob/main/training/TRAINING.md) 指向回放、标签和模型导出流程，主要大文件不随仓库提供。本轮不增加训练工程，也不下载或移植权重。

上述“机会价值”是我们据差异提出的设计假设，不声称 Fusion 已实现了相同的安全期限判断。它是否改善续 Spin 或胜负必须在本项目验证。

## 4. 对下一轮 P3 的具体影响

保持[既定计划](BOT_CHATGPT_OPTIMIZATION_PLAN.md)，不把参考调研替代优化或算作已完成P3：

1. 先用现有根/规则用例做有界转移核查：可见垃圾到时与抵消、非消行上升、空HOLD后的活动块/下一块、出生和死亡终态。分开报告确定的状态错误与未知洞位近似，不扩展成新一轮宽泛诊断。
2. 优先选一个证实的主要模型误差修正，冻结搜索和权重。若核查不支持模型改动，再登记单一估值假设，例如“压力下不可及时兑现的B2B存量被高估”；不能仅凭外部代码确认该假设。
3. 估值候选如果成立，保留已产生攻击与未来机会的分离，并有失败判据：预测更好却不改善同预算开发对战，不进入晋级；更多Spin、更长B2B不是替代指标。
4. 仍按双方Sim PPS=1、额度bot_chatgpt:botris=1:1.3、主体1000块上限、先到3胜比较；独立验收与P4门槛不变，单跑实测至少8 PPS。不得使用测试类型/对手身份切换策略。
