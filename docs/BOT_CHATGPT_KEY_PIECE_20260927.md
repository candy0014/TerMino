## 关键块的含义

关键性来自地形对特定块的需求，不能等同于攻击量。已经形成的 T Spin、其他块的 Mini Spin、四消和全清均可成为关键消行；低攻击的 Mini 也可以因为适配槽位、维持 B2B 而有价值。普通消行不是主要识别目标，仅在没有现存 B2B、能明显减少覆盖洞时允许作为修复出口。

这是有界的机会估值，不声称数学上证明了最优路线必然使用某块，也不声称识别了所有好地形。

## 评分过程

1. 每次真实决策开始时，从可见当前块、NEXT、HOLD 识别具体关键落点和一次合法准备可以补成的结构。公开袋尾只有唯一余块时，沿用已有的确定性预览补全；不推测多块袋尾的顺序。
2. 集束节点复用这些落点，并跟踪真实消行导致的坐标下移。搜索中新形成的开放 I 四消可直接补充识别。每个落点都校验实际出生、SRS 的第一个成功踢墙、最后旋转、Mini/完整 Spin 和消行条件。
3. 在最多四次未来放置内，核对 NEXT/HOLD 的实际消费顺序。等待块必须有合法的不消行安放路线，并保持同一关键块的格子、消行数和 Spin 分类；任一步发生未知垃圾上涨或死亡，就放弃这份估值。
4. 在棋盘副本中放置这些必要准备/等待块及关键块，按消行后的剩余地形评分。准备路线完整重放规则，包括攻击、B2B、combo、垃圾时钟和 HOLD。只把所得值用作终端评分，不把虚拟结果写入真实棋盘、攻击、reward、B2B 或垃圾状态。
5. 已完成结构使用完整的正向评分增益；一次必要补形的弱结构获得一半增益。真实落块补成结构时，另给 `min(240, 0.1 × 正向增益)` 的终端奖励。奖励不累加进 reward，下一节点会重新判定；已有有益完整结构时优先使用它。

准备不仅包括补行缺口，也包括补旋转所需的顶盖/角格。额外处理了“三行 I 井上方有阻挡，准备块先清掉阻挡行并补成第四行”的情况：准备前四个关键格可能不连续，不能直接套用一个旧 I 落点。

为控制成本，通用结构在每次真实决策开始时识别一次；束内不会对每个节点重新做完整补形枚举。一般弱结构的候选准备块来自当前、下一块和 HOLD，缺口行最多四格；弱结构信用仅用于前三层。等待路线采用有合法性证明的有限贪心安放，可能漏掉需要其他等待落法的机会。高于 16 行或已经发生抽象垃圾上涨的节点沿用原评分。这不是通用多步搭建规划器。

## 跨相邻放块复用

缓存由现有的 **线程级全局 `workspace`** 内的评估器持有，`search.update()` 和下一次 `getpos()` 不清空它；初始化/更换上下文时重建。

- 棋盘缓存比较完整 40 行和出生节点，保存识别结果与空结果。
- 路径缓存保存必须为空的路径格、让较早 SRS 踢墙失败的实心格，以及具体落点和 Spin 分类。棋盘其他位置变化时仍可复用；依赖格或旋转条件变化时失效。
- 关键计划缓存还比较 NEXT 前缀、HOLD、HOLD 开关和前次消行状态。每次使用都按当前深度、策略、B2B、combo 和垃圾截止时间重算评分，缓存不保存旧分数。
- 空 HOLD 后，上游评分回调的 NEXT 比实际队列少推进一格。本实验仅校正关键块预估的供给，避免再次预估已经使用的块；原基线物理评分字段保持不变。新增了真实原生树回调的独立队列游标检查。

## 验证与产物

独立前向移动枚举与宿主 BFS 核验了关键落点、92 个准备计划及 Mini/完整 Spin 分类；包括 72 个独立 Spin 检查、弱结构补全、阻挡行清除、空/非空/禁用 HOLD、未知来块、垃圾截止时间、死亡终止和缓存失效。

341 个历史根局面、24,355 个实际候选转移中，所有原物理字段均一致；9,155 次评分发生变化。关闭缓存与跨根复用缓存得到逐值相同的评分，见 `runlogs/chatgpt_key_piece_20260927/cache_v3.jsonl`。这证明缓存没有改变这些样本的评分，不代表胜率提升。

默认配置定向回归 8/8，通过；开启新实验的主程序及定向回归 3/3，通过。ASan/UBSan 检查通过；LeakSanitizer 在沙箱内受 ptrace 限制，已按授权在沙箱外完成。未重跑 Windows 或无关全套测试。

最终汇总见 [FINAL_VERIFICATION.json](../runlogs/chatgpt_key_piece_20260927/FINAL_VERIFICATION.json)。最终候选为 `runlogs/chatgpt_key_piece_20260927/key_piece_v3/`，程序 SHA256 为 `349aabe2cbfb331ea887c6c99ac9e4c08e71b05afcf994a22d3981d179d11b75`；冻结程序及归档中的全部源码均已与元数据及当前源码核对。138 个规则、运行时和对手共同源文件的哈希保持一致。`key_piece_v1`、`key_piece_v2` 及其运行记录保留为中间版本。

## 使用与复验

```sh
cmake -S . -B /tmp/tetr_key_piece_build \
  -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON \
  -DTETR_CHATGPT_KEY_PIECE=ON
cmake --build /tmp/tetr_key_piece_build --target tetr bot_chatgpt_key_piece_test -j 2
ctest --test-dir /tmp/tetr_key_piece_build --output-on-failure -R '^bot_chatgpt_key_piece$'

cmake --build build --target bot_chatgpt_key_piece_probe -j 2
build/bot_chatgpt_key_piece_probe \
  runlogs/chatgpt_strategy_20260927/merged_inputs/roots.log cache
```

新建构建目录只开启一个实验；不能与其他 `TETR_CHATGPT_*` 实验叠加。探针还支持 `physical`、`fixed`（固定 16 轮）和 `timed`（含根识别开销的 100 ms 请求预算）模式。计时仍在原生迭代边界检查，不是严格的墙钟硬上限。
