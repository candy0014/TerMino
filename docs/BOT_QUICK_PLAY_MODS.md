# Quick Play BOT Mod 适配

`bot_while1`、`zzztoj_botris`、`bot_chatgpt` 在未启用新增 Mod 的基础快速游戏中保留完整的自由游玩搜索、评分和搜索宽度，攻击、推进器及经验由实际 Quick Play 引擎结算。启用 Mod 后使用主程序的方块定义、移动规则和落块结算，再按各自的场地评分搜索。适配入口为 `Bot::QuickPlaySearch`。

基础 QP 不将散消一的补偿攻击和消行经验加入原战术评分，保留各 BOT 已验证的攻击规划；不是缩减为两层的替代策略。已宣布 Windup 作为未来到达的垃圾传给原搜索。疲劳的永久实心行转为搜索场地的地板，落点转换回实际坐标并检查原场地可达性。原搜索不能表示的隐藏区、尺寸、操作或攻击设置由规则搜索处理。While1 使用原有完整宽度搜索，其计算耗时也与自由游玩一致。

| Mod | BOT 搜索和预判 |
| --- | --- |
| NH / rNH | 遵守禁用 HOLD；rNH 使用实际可见的一项 NEXT、随机块及 Mini 规则，不猜测隐藏序列。 |
| MS / rMS | 使用本局垃圾图案、混乱度、攻击及经验规则；保存计时垃圾格，并预测消行等待。 |
| AS / rAS / 扩展 AS | 根据主程序识别 Spin、Mini、Void；保存上次消除及历史，计算重复惩罚、计时垃圾衰减和经验折扣。rAS 的立即死亡优先排除。 |
| EX / rEX | 使用楼层等待表、瞬间上涨、经验、下坠、停层惩罚和疲劳规则。 |
| GV / rGV | 搜索普通重力和 20G 的实际可达位置；后续预测包含重力增长及跨层加速。 |
| VL / rVL | 使用实际矮场地、受击及抵消倍率，保留小数抵消余量。 |
| DH / rDH | 保留垃圾格来源，计算挖掘、BLIGHTED、攻击转换和补行；rDH 只保留游戏允许的 Spin。 |
| BF / rBF | 将自伤加入队列；rBF 按本局规则处理发送与抵消，避免把无法抵消的攻击当作减压。 |
| SE / rSE | 计算单消限制、攻击抑制及抵消前的自伤，评估其对后续版面的影响。 |
| SB / rSB | 支持从 4×4 到 20×20 的场地；预测每 20 行的成长、左右新增列和垃圾扩展。rSB 使用零 DAS 的整段滑移，支持与 20G 组合。 |
| IN / rIN | 显示规则由主程序执行；BOT 使用当前真实场地快照，保留隐藏的实格及垃圾格。 |
| Fool 及逆位 2026 | 搜索真实特殊块的形状、旋转、出块位置和攻击；适配暂存、新块包中的特殊块与连续抵消产生的 I5。 |

组合按同一套落块流程结算，包括抵消正在上涨的行、已预警的 Windup、疲劳的永久垃圾、计时垃圾和场地成长的先后顺序。场地保留主程序的 100 行隐藏区；出块及 HOLD 均检查 Clutch，方块过宽时沿用主程序的失败判定。

Mod 评分有独立配置：While1 在十列场地保留其原有地形评价，其他宽度使用可随宽度变化的地形项；Botris 沿用 v0.8 的地形项及攻击、连击倾向；ChatGPT 沿用攻击、B2B、挖掘与中间危险度权重。三者都加入实际推进器经验和 Mod 自伤，先保留能够继续生存的候选。搜索宽度控制计算预算和保留分支，Mod 搜索当前最多搜索 While1 五层、Botris / ChatGPT 四层可见块。

Quick Play 的散消一有攻击及消行经验补偿，搜索会降低经验相对攻击的权重，并奖励实际较强的攻击，避免只靠单消获取即时收益。地形评分保留最多四行、能够从上方进入的四消槽及其可填空缺；四消槽可以建在已有方块或垃圾上，封住的洞不会得到准备奖励。落点按相同位置的实际无 Spin / Mini / Spin 分类去重，执行仍保留真实踢墙记录。While1 的未建立 B2B 状态不会因历史负数编码得到错误奖励。

未知信息采用保守预测：小数攻击向下取整，未来垃圾洞位使用独立的代表样本，未宣布的对手攻击只计入预计压力；不读取玩家的未来方块、垃圾 RNG 或攻击 RNG。已宣布的 Windup 则按其实际数量和到达时间处理。普通七块包的可见补集只剩一块时可推断最后一块；随机块、Fool 和连续抵消的变异包禁用该推断。

默认 Mod 的场地尺寸均覆盖。预测器的范围为宽 4～32、高 1～40；反重力、每块多次暂存仍明确报告不支持。此入口适配上述三个 BOT，其他 zzztoj 策略继续使用各自的兼容性判断。ChatGPT 的编译期实验评分同样用于基础 QP 的原搜索入口，Mod 使用这里的独立评分。

验证由 `bot_quick_play_mods_test` 执行：单项正常 / 逆位及组合、特殊块、4 / 5 / 10 / 20 宽、零 DAS 与 20G 的路径验证；攻击、抵消、重复惩罚、补行、成长、Windup 与疲劳的实际引擎对照；多局连续落块；搜索状态隔离和取消。测试同时检查搜索不会推进游戏的方块、垃圾或攻击 RNG。

`bot_quick_play_attack*` 使用三个 BOT、不同实际七块包、有 / 无垃圾压力和默认 / 小搜索宽度，每局连续落块 100～160 次，压力用例跨过第一阶段疲劳。除合法路径和存活外，还检查实际攻击、多行消除及四消 / Spin；允许原 BOT 在部分块包中使用持续 B2B Spin 单消出攻，要求其有实际攻击和连锁，防止策略退化为普通单消。另有原搜索配置、已知预警、不同疲劳地板的桥接验证；`--free-benchmark` 可运行相同序列和配置的自由游玩对照。

全速或高 PPS BOT 在搜索、等待期间保留当前活动块的位置，完成等待后才应用选定落点。垃圾上涨按活动块的位置更新阴影、抬升方块，并使旧落点失效；HOLD 后续同样处理。绘制继续使用差分更新。旧回放中的清除操作以终端实际画出的活动块为准，兼容曾经误记为 BOT 计划落点的清除位置。

`garbage_rise` 覆盖各普通块、全速 / 高低 PPS、HOLD 后续、着地 / 未着地和阴影开关，比较累计 ANSI 画面与完整重绘；`autoplay_timing` 还通过实际落块流程检查搜索期间连续上涨后的已落下方块与垃圾。保存的回放审计同时检查每次移动、疲劳上涨和落块后的画面；存在 `replay/bug.txt` 时会加入 `quick_play_bot_saved_replay`，比较正常与积压播放的几何、垃圾随机状态和 ANSI 画面。

2026-10-12 的 100 块对照样例：实际七块包种子 123，搜索宽度 300，按块计时 2.5 PPS，入场 / 消行延迟均为 0，基础 QP 的受击倍率为 0。以下为实际引擎累计攻击；墙钟预算和原 BOT 的平分选择会使具体结果有少量变化。

| BOT | 自由游玩 | 基础 QP（恢复原搜索） |
| --- | ---: | ---: |
| While1 | 72 | 75 |
| Botris | 49 | 58 |
| ChatGPT | 84 | 89 |
