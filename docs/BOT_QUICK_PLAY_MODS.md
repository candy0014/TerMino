# Quick Play BOT Mod 适配

全部十个 BOT 已接入共享快速游戏规则搜索：`bot_while1`、`bot_candy0014`、`bot_mech`、`zzztoj_botris`、`zzztoj_toj`、`zzztoj_dig`、`zzztoj_qq`、`zzztoj_c2`、`bot_chatgpt`、`bot_coldclear`。终端和 OpenGL 使用同一实现。

兼容原搜索的场地和规则继续使用各自原生规划。显示、普通洞位/压力变化、禁用 HOLD 不会单独触发另一套战术评分。原生规划不能表达的尺寸、特殊块、攻击资格或动作限制交给 `Bot::QuickPlaySearch`：使用主程序的方块、移动、Spin 检测、落块、抵消和 QP 奖励规则，再使用对应 BOT 的评价。所有返回目标均由共享移动模型验证。

| BOT | QP 策略 |
| --- | --- |
| While1 | 兼容时保留完整原生搜索；规则搜索在十列场地使用原地形回调，其他宽度使用可随宽度变化的地形项。 |
| Candy0014 | 兼容时保留原搜索；其地形函数被独立提取，用于真实 QP 结算后的场地，包括成长和特殊块。 |
| Mech | 原来的固定开局脚本依赖固定方块包及版面；QP 使用通用可达搜索，保留其全消目标和 Candy 地形偏好。其他模式的开局脚本保留。 |
| Botris / TOJ | 兼容时保留各自搜索；十列规则搜索调用各自原生地形评价。不同宽度使用相应的高度、空洞、转折、井和覆盖项。 |
| Dig | 保留原生挖掘地形及无 HOLD 风格；规则搜索提高真实挖掘收益，使用 QP 的真实垃圾来源和补行。 |
| QQ / C2 | 保留各自原生搜索、地形参数及无 HOLD 风格。窄场地绕过固定出生点图，使用相应的动态宽度地形项；不会初始化会在四列崩溃的原图。 |
| ChatGPT | 按实际完整 Spin 能力奖励有效 Spin 消行，零行旋转不获得该完成奖励。Allspin 在可表示场地继续使用原生搜索树，携带真实重复类别、B2B 和逆位即死判断；复杂场地进入规则搜索。按实际暂存、旋转、移动、垃圾、块型和可用空间调整资源与地形估值。通用机制不按 Mod 名称分流。 |
| Cold Clear | 兼容时保留原生规划；十列规则搜索调用原生地形评价，其他宽度扩展高度、空洞、覆盖、井和表面项。保留消行/Spin/全消偏好。 |

原生快照将疲劳永久垃圾作为地板，保留所有可表示的灰格和已公布 Windup；转换回真实坐标后检查出块、HOLD 和目标可达性。20G 的活动块和 HOLD 换入块先落地再验证。不能表示的隐藏区、计时垃圾或尺寸转入规则搜索。不可游玩的底部不计为普通堆叠。Fool 与连续抵消变异包保留实际块型 ID，防止 NEXT/HOLD 中同族的不同形状覆盖当前块；规则搜索无结果时使用实际场地和块型的公共回退。

ChatGPT 的原生 20G 搜索按动作逐次落地，并验证实际返回路径；不会因沿用其他 BOT 的可用性限制而把同一机制强制降入较弱搜索。

| Mod | 规则搜索和主程序的共同语义 |
| --- | --- |
| EX / rEX | 楼层等待、瞬间上涨、经验、下坠、停层和疲劳。 |
| NH / rNH | 禁用 HOLD；rNH 仅使用实际一项预览、随机块及 Mini 规则。 |
| MS / rMS | 垃圾图案、混乱度、计时格、攻击及消行等待。 |
| GV / rGV | 普通重力、20G 可达位置及后续重力变化。 |
| VL / rVL | 矮场地、受击/抵消倍率、小数抵消余量和集中洞位。 |
| DH / rDH | 灰格来源、挖掘、BLIGHTED、攻击转换、补行及 Spin 限制。 |
| IN / rIN | 主程序执行显示规则；BOT 使用真实的当前场地快照。 |
| AS / rAS / 扩展 AS | Spin/Mini、上次操作、历史、重复惩罚、计时垃圾、经验限制；立即死亡优先排除。 |
| BF / rBF | 自返垃圾和发送/抵消限制，不把无法抵消的攻击当成减压。 |
| SE / rSE | 消一限制、攻击抑制及抵消前的自返垃圾。 |
| SB / rSB | 从 4×4 到 20×20 的成长、新列和垃圾扩展；rSB 的零 DAS 整段滑移及其与 20G 的组合。 |
| PN / rPN / F26 / rF26 | 实际特殊块、旋转、出生位置、暂存和攻击；包括连续抵消产生的 I5。 |

组合按相同的共享落块顺序执行。未知垃圾洞使用独立代表样本；不读取未来方块、垃圾 RNG 或攻击 RNG，也不消耗玩家随机状态。七块包的可见补集只剩一块时才推断尾块；随机块、Fool、连续抵消变异包禁用该推断。

默认搜索宽度 300 下，ChatGPT 的原生搜索预算为 100 ms，规则搜索为 90 ms，另有公共验证开销，目标约为 10 次决策/秒。加入 Mod 不缩小用户宽度：规则搜索每层保留设定宽度，轮流扩展各可见深度及其他候选，取消原来的 17 个默认候选、48 个上限和固定七层限制。已知 HOLD 可以延伸可见队尾，但必须先确认所有允许的未知当前块都能出生；不猜测其身份。落点枚举和分支评分检查截止时间，并非每次搜满预览。对称旋转按实际占用格及 Spin 类别去重。游戏配置的 PPS 仍控制实际速度，rMS 等强制消行延迟也真实计入游戏时钟。

ChatGPT 的后续调整按机制生效：没有 HOLD 时降低对特定块和深井的依赖；瞬间重力、整段滑移或不能逐格下降时提高埋洞代价；挖掘按可用高度和已知垃圾压力调整，保护实际垃圾出口；大块增加空间储备代价。均匀随机且无法 HOLD 的短预览，在预算允许时对全部允许块计算下一步期望和较差结果，不能挑选有利的未知块。普通原生搜索也使用同一能力评分，其他 BOT 的评分不变。

十列标准 SRS+、完整移动能力的规则搜索复用预计算几何图，保留同格占用下的普通、Mini 和完整 Spin 分支；更窄/更宽的场地、特殊块、20G、零 DAS 和禁用操作继续使用实际移动模型。规则搜索的结算由共享 QP 模拟完成，按设定宽度为 HOLD、预览消耗、B2B、攻击资格和 Allspin 重复类别保留继续路线。可见块的 Spin 机会只作叶节点评价；原生快路径对未来补行作保守空间计费，现有计时垃圾或无法表示的场地进入完整规则搜索，rAS 返回目标还通过真实结算复核。自返垃圾与场地惩罚同样扣除。

可用范围是场宽 4～32、高 1～40；反重力、每块多次 HOLD 仍明确不支持。只有 ChatGPT 支持既有的手感模拟入口。支持 Mod 不表示所有组合都能无限存活：例如未旋转形状超过雪球场宽会按真实规则出块失败，BOT 不自动旋转出生块、跳过块或削弱 rAS 的死亡惩罚。

验证使用全部单项变体、332 种两两组合、均衡的高阶组合、特殊块、不同场宽、零 DAS、20G 和真实连续落块。高度测试入口是 `bot_quick_play_altitude_benchmark`，批量工具为 `tools/benchmark_quick_play_bots.py`：

```sh
cmake --build build --target tetr_bot_tests -j 4
python3 tools/benchmark_quick_play_bots.py --suite singles --output /tmp/qp-singles.jsonl
python3 tools/benchmark_quick_play_bots.py --suite mixed --output /tmp/qp-mixed.jsonl
```

`--before` 可传入修改前冻结的套件二进制，按相同种子、时限、设置及同一工作线程/CPU 核心成对比较。默认种子 123、456、789，默认 20 秒游戏时间，最高 10 PPS；搜索慢于 100 ms 时计入实际耗时。消行/进块等待计入游戏时间，画面睡眠由受控时钟代替。测试不访问本地玩家数据。

`bot_quick_play_mods_test` 比较预测与真实落块、Windup、疲劳、抵消、重复惩罚和成长；原生策略对照同时覆盖埋洞版面及原生只保留较强 Spin 的情况。既有攻击、联网、回放及垃圾上涨画面回归继续保留。规则核查及缺项见 [规则核查报告](QUICK_PLAY_AUDIT_20261020.md)。
