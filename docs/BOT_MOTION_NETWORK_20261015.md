# BOT 活动块传输（2026-10-15）

低 PPS 动画和模拟手感两种 BOT 路径均已接入现有活动块协议。完整对手版面可以收到横移、旋转、软降和硬降过程中的位姿；本次不修改协议格式，兼容现有公网服务 `wss://termino.candy0014.icu/ws`，不需要重启或更新服务器。

## 实现与手感约束

- 每一步先完成本地状态与绘制，再调用已有活动块发送入口。使用非阻塞 UDP / 异步 WebSocket 队列，没有新增等待回包或攻击确认。
- 只有 BOT 调用选择显示周期合并；手动输入继续走默认即时路径。同一约 8.33 ms 周期内多次 BOT 位姿只保留最新一个，补发也检查周期；停止移动后仍会补发末次状态。棋盘基准变化时仍立即发校准快照。
- BOT 的联机等待循环使用现有活动块轮询间隔：支持混合同步时约 120 Hz，其他情况仍为 50 ms，避免移动状态在旧 BOT 的 50 ms 轮询中滞留。原有接收预算、远端绘制预算和输入优先逻辑继续生效。
- 仅缩略图或隐藏订阅不发送活动块，避免人数增加时多发动画数据。小图仍使用固定方块投影。攻击和落地校准使用原有通道。

生产改动位于 `src/engine/autoplay_adapter.cpp`、`src/engine/autoplay_handling.cpp`、`src/network/multiplayer_channel.cpp` 和对应声明。`runlogs/bot_motion_changes_20261015.patch` 保存相对本次任务前的改动。

## 功能验证

`autoplay_network` 使用真实 relay、两个网络客户端、实际 BOT 动画函数及接收端时间线，检查中间横移和旋转、最后状态还原、小图和隐藏订阅，以及 1,000 次同周期位姿变化只产生一个待发末状态。还检查周期未到时不能提前冲刷。连续两块落点相同时，必须按本轮序号确认完成，不能只比较位置。

- 本机 UDP：两种动画各收到 5 个移动位姿；小图和隐藏订阅各收到 0 个活动块。普通低 PPS 过程约 400 ms，模拟手感路线约 78 ms。记录：`runlogs/bot_motion_sequence_network_evidence_20261015.txt`。
- 公网 WSS：最终两种动画分别收到 4 / 5 个移动位姿，均按本次序号还原最终位置。允许可替换视觉状态合并，不承诺拥塞时逐帧保留所有中间动作。记录：`runlogs/bot_motion_final_public_network_20261015.txt`。
- 自动手感、PPS 时序、场景、自适应视图、混合同步及 WebSocket 回归通过。首轮新增测试遗漏了 Replay 依赖，修复测试夹具后通过；公网新增测试曾把上一块相同落点当作完成，已改为检查本次序号。失败日志保留。
- 最后补发周期检查后，网络、混合同步、WebSocket 三项回归全部通过：`runlogs/bot_motion_final_network_ctest_20261015.txt`。

## 操作响应测量

每场 240 次真实 Win32 控制台输入，验证自身位姿实际写入 VT 输出。在线场景均连接真实公网服务器。BOT 对手使用固定策略驱动生产动画函数，以排除决策搜索耗时波动；其自身终端输出独立丢弃，接收端真实绘制对手，再测自己操作。

| 场景 | 自身输入→VT p50 / p95 | 自身输入→VT 最大值 | 主循环 p95 |
|---|---:|---:|---:|
| 改前离线 | 1.132 / 1.705 ms | 4.678 ms | 0.957 ms |
| 改后离线 | 1.156 / 1.653 ms | 2.352 ms | 0.974 ms |
| 普通联机 120 Hz，改前 | 1.054 / 1.513 ms | 4.849 ms | 1.569 ms |
| 普通联机 120 Hz，改后 | 1.057 / 1.440 ms | 2.260 ms | 1.596 ms |
| 最终 BOT 低 PPS 动画 | 1.065 / 1.476 ms | 5.144 ms | 1.361 ms |
| 最终 BOT 模拟手感 | 1.130 / 1.452 ms | 2.160 ms | 1.436 ms |


最终 BOT 两场分别发送 160 / 155 个活动块移动包，接收端提交了 177 / 175 个带可匹配序号的远端状态（含校准），确认接收端确实在显示 BOT 动画。最终 BOT 发送→VT 中位数约 225 / 220 ms，p95 约 238 / 236 ms；公网传播时间仍存在。两种 BOT 的源端周期均按 2.5 PPS 驱动。

普通联机改前/改后使用同一输入与渲染测试，默认即时移动发送保持原路径；后续只补充了待发状态的周期检查。最终 BOT 测量包含这个检查。首轮最终 Wine 复测在准备后出现未处理的页错误，未进入测量；测试器补齐两个模拟终端共享 `std::cout` 的渲染锁后，两项均通过。未确定该 Wine 错误的原因，失败轨迹保留，未计作性能样本。

这是 Wine 中的输入→VT 输出时间，未包含实体键盘和显示器刷新。短时测试未见普通手动联机操作的响应退化，不能保证所有机器、终端和线路完全零影响。完整数据及可执行文件哈希见 `runlogs/bot_motion_summary_20261015.json`，每个 JSON 同前缀有输入 CSV 和终端轨迹。
