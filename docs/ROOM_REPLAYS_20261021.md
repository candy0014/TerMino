# 房间多人回放（2026-10-21）

终端与 OpenGL 共用录制、传输、房间历史菜单和播放器。需要同步更新服务端；能力通过
`!replay-v1` 协商，原有 join-v3/join-v4、UDP/WebSocket 对战及旧录像入口继续保留。
已按用户要求同步服务端至 tetu 公网，部署记录见下文；未发布 GitHub 版本。

## 使用方式

- 参战者结束自己的操作时，照常自动保存个人回放；淘汰后不必等其他玩家结束。
- 在结束棋盘或结果统计页按当前绑定的“保存回放”键，可以下载整场录像。纯观众也能使用，
  不要求本机有参战计时或个人回放。若本场仍在进行或服务器正在收尾，会显示等待状态；
  Esc 可取消，网络心跳和上一场补传继续运行。
- 完整下载通过校验后，升级同一条本地近期回放，再进入现有命名保存界面。下载失败、取消、
  录像已淘汰或房间已删除时保留个人文件。受保护或被外部修改的文件不会自动替换。
- “设置 → 网络 → 房间对战回放”，以及游玩房间面板中的同名入口，列出本房间最近 30 场
  已开始的对战。每场显示时间、人数、时长、完整性及房主终止状态，可查看或另存为。
  另存副本不参与近期缓存淘汰。
- 播放时默认选中录像中记录的本人；Tab 沿用观战切换，结束后打开结果页。暂停、空格、
  `-/+` 倍速及方向键前后 10 秒控制整场时间轴。统计页的方向键只控制统计。Esc 先关闭
  统计，再返回原菜单；保存键另存包含所有玩家的完整源文件。

列表、下载取消、观看、另存命名和返回均有键盘路径；图形菜单同时支持共享鼠标命令。
观看历史时保持实际房间连接，并退出准备状态。录像使用隔离的会话和网络视图，不发送
攻击、淘汰、准备或结束对局命令。

## 生命周期与身份

录像在服务端进入 Playing 时建立，固定当时的参战名单。正常结束、房主 EndMatch、旧的
房主切场及取消路径在清空旧状态前封存记录。准备/倒计时取消不新增历史。
上一场上传以房间实例和 match epoch 绑定，可以在下一场准备期间继续；不依赖当前槽位
是否仍参战。房主停止标记为 HostStopped，没有胜者。

服务端保留最近 30 场已结束对战，另有当前正在进行的一场。房间为空删除时，索引、轨道
文件及已生成的下载文件一起释放。迟到请求不能重建历史；同名新房间有不同实例。
用户已下载、另存的文件不受服务端清理影响。

每条轨道使用固定 actor ID，昵称只用于显示，并附本场编号。下载文件保存 viewer ID；
同名玩家、改名和槽位复用不会改变归属。每个持久档案在其 `replay` 子目录保存匿名
`viewer-*.id`，用于重连后选择原轨道；本地个人录像也保留房间/对局/actor 的兼容头部
元数据，供近期列表恢复关联。匿名身份只选择视角，不授予上传或跨房间下载权限；上传
仍校验原连接凭证。连接 token 和匿名档案标识不会写入可分享的多人录像。

## 数据与边界

`TETR_MULTIPLAYER_REPLAY_1:` 是长度分隔的二进制容器，继续附原有文件校验后缀。
读取器按 magic 分流，单人及本地双人仍保留原有读取兼容性。每条轨道包括：

- C：实际规则、地图与随机种子的配置头。
- O：原有操作记录，包含独立真实时间和规则时间。
- B/M：完整语义棋盘与解析后的绝对移动；来源独立于在线观战订阅和缩略图预算。
- F：结束时的原始统计；容器另存淘汰、击杀者、目标变化及结束原因。

多人播放器用一个调度器推进所有轨道，通过现有远端棋盘适配器和观战视图呈现录制状态。
它不重新计算网络攻击或另写玩法规则；原始操作流同时保留在容器内。暂停、倍速、定位
共用已有回放时钟及键盘控制。回退为每个玩家恢复最近的完整棋盘，再推进到同一个目标
时间。已结束玩家保持冻结，结果统计使用录制时间和数值。

录制回调只追加内存队列。客户端临时文件写入和上传预读在共享 I/O 工作线程进行，网络
轮询只发送有限窗口。分块包含偏移与校验，支持重复、乱序和重传；只有连续确认的字节
才计入完成。最终操作块、统计、总长度和校验均完成后，服务端确认该轨道。

服务端用临时文件保存轨道，不把 30 场全部内容常驻内存。缓存目录有专用格式标记和
操作系统锁；正常退出删除，后续启动只清理标记有效且已无进程持锁的遗留目录。
客户端的临时上传文件也按所有权释放，不使用个人 `.tetr` 作为测试或服务器缓存。

每轨道上限 64 MiB，下载容器上限 256 MiB。对局结束后最多收尾 15 秒；断线、旧客户端
未提供录像或达到存储限制时保留可用前缀并标为不完整。它可以显式另存，界面标出缺失
轨道，不能自动覆盖个人回放；缺少的统计不使用观看耗时补造。

## 验证与回退

新增回归为 `room_replays`、`room_replays_websocket` 和 `room_replay_graphical`。
前两项使用隔离运行目录和本地服务端，覆盖房主停止后的跨场补传、分块去重/乱序、同名、
槽位复用、持久身份重连、纯观众结果页保存、精确 30 场淘汰、断线前缀、不完整副本保护、
房间删除及同名重建。图形回归使用无窗口 Session，覆盖默认本人主板、全局暂停/倍速/
前后定位、结果、中文命名另存和返回。另覆盖零高度棋盘及有限序列耗尽后的结束录像。

Linux 已构建 `build/tetr`、`build/tetr_gl`、`build/tetr_server`，独立无图形服务端构建
通过，并确认其运行依赖不含 SDL/OpenGL/字体库。全量 177 项测试通过，其中对运行时限
敏感的 Bot 测试单独运行；最后的缓存读写修正后，相关 26 项复查全部通过，包括 UDP、
WebSocket、无窗口图形回放和架构边界。多人回放实现回归结束时，个人 `.tetr` 的 200 个
文件与实施前 SHA256 逐一一致。未显示测试窗口，未修改原生验收状态。
原生 Windows 的构建、图形和设备输入尚未在本机验证，验收记录继续 pending。
