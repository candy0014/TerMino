# QP2 自动给伤校准（2026-10-12）

数据来自 [官方 Tetra Channel 公共 API](https://tetr.io/about/api/#recordsleaderboard) 的 `zenith_global@2026w40` 和 `zenith_global@2026w41` 两个完整周榜。每个周榜分别取低于 25、100、225、375、550、750、975、1225、1500、2000、3000、4000、5000 米的前 100 条成绩，去重后有 **2501 局**。其中 **2315 局无 Mod**；排除稀疏尾部偏离采样锚点过远的成绩后，**2297 局**用于强度曲线。

这是按海拔分层的周最佳成绩样本，不是所有玩家或所有对局的随机样本。两周可能包含同一玩家。统计分析的是公开成绩中的整局统计字段，没有将它们当作逐帧回放数据。

攻击 APM 使用 API 的 `aggregatestats.apm`，包含被抵消的攻击；实发 APM 使用 `garbage.sent / finaltime`，收伤使用 `garbage.received / finaltime`。最后两项均换算为每分钟。收伤已经包含正版的倍率、受击保护、目标选择和 Windup 截断，不能作为原始攻击再直接套一遍倍率。整局统计也不能说明该海拔的瞬时收伤率。

本地模拟使用攻击 APM 均值构建线性插值的对手强度曲线，移除了此前额外加 5 的强度和旧的整数截断 / 均匀 1–5 行攻击分布。超过 4690 米时沿用样本较充分的 2880–3846 米斜率外推，并限制为 1000 APM；这部分是模拟参数，数据支持较弱。

小攻击的组成来自无 Mod 样本的消行计数：将普通一/二消、三消/mini 一消、Spin 一消/mini 二消、四消/Spin 二消、Spin 三消映射为 1/2/3/5/7 点攻击的近似模型，分六个海拔区间使用实际计数比例。它近似包含 B2B 奖励；成绩摘要无法恢复当时的连击、抵消和 Surge 时间。大攻击概率（1%–8%）及其大小增长使用本地模拟参数，不能视为实测逐包分布。真实服务端的攻击对象选择算法未公开，因此本地模拟保留基于受击权重、危险状态、特定逆位 Mod 的垃圾保护和受击保护的近似目标选择，不能声称复刻真实房间的全部匹配过程。

攻击生成按 60Hz 的游戏时间进行随机采样，不因移动循环或终端帧率变快而增加给伤。暂停冻结，撤回恢复随机流和调度状态，回放只使用已记录的攻击。对手强度不额外乘 Mod / 疲劳倍率；这些因素在实际接收时结算一次。

Windup 的确定规则对照 [官方客户端](https://tetr.io/js/tetrio.js) 与 [QP2 规则观察文档](https://github.com/MrZ626/modern_tetris_cn_community/blob/main/io_qp2_rule/full.md)：

- 先结算高度惩罚、抵消惩罚、受击保护和倍率，再检查触发阈值。普通模式为 8 行，VL/rVL 为 16 行（客户端的明确分支）。
- 普通容量为 16；从 4000 米开始，每 500 米增加 1；VL/rVL 将容量翻倍。分为最多四段，大段排后，超出容量的部分丢弃。
- 首段在预警开始 1 秒后接收，后续段每隔 0.5 秒接收；整个 Windup 占 `2 + 0.5 × 段数` 秒。新的 Windup 排在前一个结束后，普通小攻击仍可到达。
- 各段保持已经结算的行数，接收时不再重复乘倍率或套受击保护；进入缓冲时才增加受击保护并开始垃圾等待。左侧独立警告区域显示对应段数的感叹号，脉冲换色时保持符号可见。
- 开启连续抵消时，客户端对“加罚后的攻击总量”设上限，保留原始攻击下限；大攻击不再额外叠加整段上限。

复现统计：

```sh
python3 tools/analyze_qp2_pressure.py /tmp/qp2-sample --download --output /tmp/qp2-summary.json
```

脚本仅调用公开 API，每次请求间隔 1 秒并复用缓存。[本次汇总数据](qp2_pressure_sample_20261012.json) 包含均值、中位数、10/90 分位数及消行组成，可在不联网的情况下审阅。

验证：`qp_pressure_test` 检查接收顺序、阈值、倍率只结算一次、截断、回放、撤回、重绘与布局；固定海拔长期采样检查模拟 APM 与校准值相符，并比较一次长步进和多次 60Hz 步进的随机流。`qp_pressure_reference_test.cjs` 使用原始官方引擎对照 40 组不同攻击、海拔、VL 和连续 Windup 时序。
